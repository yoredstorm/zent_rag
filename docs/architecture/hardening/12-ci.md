# CI — checks requeridos, fast vs full

Estado: **F12 implementado**. `ci.yml` (PR) + `nightly.yml` (programado).

Regla: un PR no puede romper un contrato de arquitectura sin que el check lo
diga. Nightly cubre lo caro (suite completa sin `-x`, adversarial, estabilidad
×100); PR cubre lo rápido y determinista.

---

## 1. PR (`ci.yml`)

| Job | Qué hace | Bloqueante |
|---|---|---|
| `secrets-scan` | gitleaks | sí |
| `lint` | `ruff check src/ tests/ sdk/python` desde `uv.lock` (uv fijado; `uv lock --check`) | sí |
| `pip-audit` | auditoría de dependencias prod (HIGH+) | no (continue-on-error) |
| `test` → **Architecture invariants (fast)** | contratos de arquitectura (lista abajo) | sí |
| `test` → Run tests | suite completa: `-x` solo en PR; push a master corre sin `-x` (todos los fallos visibles) + JUnit artifact | sí |
| `sdk-python`, `sdk-node`, `portal` | SDKs y portal (typecheck/lint/test/build) | sí |
| `portal-e2e` | smoke + axe con API real | sí |
| `kustomize`, `build` | manifests y build de imagen | sí |

### Invariantes rápidos (required)

```
tests/test_architecture.py                    # capas (core/infra/rag/agents...)
tests/test_terminal_transitions_allowlist.py  # transiciones terminales fuera de la política
tests/test_reason_codes.py                    # catálogo reason-codes-1
tests/test_failure_taxonomy.py                # taxonomía + literales fuera del catálogo
tests/test_adaptive_projection.py             # writers de `adaptive` = proyección
tests/test_finalization_policy.py             # jerarquía de autoridad del cierre
tests/test_finalization_enforcement_scopes.py # scopes agente > org > env > global
tests/test_finalization_golden.py             # corpus dorado (24 casos, ×100)
tests/test_run_guards_shadow.py               # tabla de guards vs ruta vigente
tests/test_prompt_assembly.py                 # bloques del prompt + inyección
tests/test_prompt_block_headers.py            # encabezados del sobre
tests/test_conversation_isolation.py          # aislamiento por conversación (×100)
tests/test_run_accounting.py                  # ledger único (agente)
tests/test_run_accounting_rag.py              # ledger único (RAG)
tests/test_provider_attempts.py               # failover visible, sin doble conteo
tests/test_run_metrics.py                     # métricas run-level + cardinalidad
tests/test_run_state.py                       # estado canónico + invariantes
tests/test_openapi_contract.py                # una sola registración por router (sin op ids duplicados)
tests/test_db_lifecycle.py                    # engine async entre loops, sin conexiones colgadas
tests/test_chaos_resilience.py                # matriz de chaos (LLM/tools/Redis/reranker)
tests/test_flags_inventory.py                 # drift de .env.example = 0
tests/test_exception_certification.py         # ratchet de except en caminos críticos
```

Criterio de cobertura (no perseguir % arbitrario): autoridad, seguridad,
aislamiento de tenant/conversación, budget, fallos de provider, finalización,
contabilidad y contratos de prompt.

## 2. Nightly (`nightly.yml`)

- **Full suite sin `-x`** (`--timeout=600`): todos los fallos visibles, no solo
  el primero.
- **Adversarial**: `test_adversarial_matrix`, `test_adversarial_generalization`,
  `test_llm_stream_fallback`, `test_llm_embed_retry`.
- **Estabilidad ×100**: 3 pasadas de las suites de estabilidad
  (`test_finalization_golden::test_estabilidad_cien_runs_por_caso`,
  `test_adversarial_matrix::test_resolucion_estable_100_runs`).
- Perf/load/chaos: viven en `src/scripts` (`perf_traffic`,
  `finalization_audit`, `load_test`) y necesitan LLM/corpus reales: se corren en
  staging, no en el runner (ver `perf-baseline.md`).

## 3. Branch protection

Marcar como **required**: `secrets-scan`, `lint`, `test`, `sdk-python`,
`sdk-node`, `portal`, `build`. `pip-audit` queda informativo hasta que la deuda
de dependencias esté en cero. La configuración vive en GitHub (Settings →
Branches), no en el repo.

## 4. Deuda

- Coverage por módulo priorizado: falta el reporte (F14).
- Chaos subset en nightly: pendiente de F11 (harness de inyección).
- Perf smoke en nightly: pendiente de un entorno con proveedor de modelos.
